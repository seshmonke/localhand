## Блокеры

1. **DELIVERED по HTTP с fake-провайдером невозможен.** Статус отправления
   хранится в памяти процесса API (`fake-provider.ts`), а
   `POST /delivery/cdek/webhook` берёт статус из `provider.getShipment`.
   Публичного dev-хука, как `/dev/payments/:id/complete`, у доставки нет.
   Переход `created→delivered` доказывает только API e2e
   (`shipment.db.test.ts`, in-process `setShipmentStatus`). Нужен либо
   dev-only API endpoint (production change, вне owns), либо браузерный e2e
   против локального CDEK-стаба.
2. **Полный `pnpm test:e2e` красный вне owns.** `buyer-flow.spec.ts` и
   `layout.spec.ts` создают физический заказ без доставки и получают
   `409 delivery_required` (`buyer-flow` — UI checkout без полей доставки;
   `layout` — прямой `POST /api/checkout`). Спеки не входят в owns 3.10;
   нужен отдельный PBI/исключение, чтобы обновить их на delivery-aware
   checkout.
3. **PR size.** 751 строка code+tests. Готовый сплит — выше.
