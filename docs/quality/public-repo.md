# Публичный репозиторий: что можно и что нельзя

Репозиторий `seshmonke/localhand` — **публичный**. Всё, что попало в
коммит, становится публичным навсегда: история не исчезает при удалении
файла новым коммитом. Правило действует для кода, docs, issue, PR,
скриншотов и логов.

## Нельзя коммитить

- Секреты: `.env`, токены, API-ключи, пароли, cookie, JWT, SSH-ключи,
  сертификаты, keystore, kubeconfig.
- ПДн реальных людей: ФИО, телефоны, адреса, email, паспортные данные,
  номера заказов, переписку, скриншоты с этими данными.
- Дампы и выгрузки БД, `.sqlite`, `.db`, бэкапы, `pg_dump`, HAR-файлы.
- Внутренние документы: договоры с реальными реквизитами, счета,
  бухгалтерия, зарплаты, private-переписка, ссылки на закрытые ресурсы.
- Прод-доступы: IP/хостнеймы VM, SSH-ключи, admin ID, токены ботов.
- Абсолютные локальные пути (`/home/...`, `/Users/...`) и имена
  пользователей в коде/логах.

## Можно

- Публичные законы и ссылки на них, юридический анализ без ПДн.
- Ориентировочные цены провайдеров и архитектурные решения.
- Тестовые данные только вымышленные: `Иван Тестов`, `demo@example.com`,
  `local-hand-demo`. Реальные имена, телефоны и адреса запрещены.
- Скриншоты с обезличенными данными; реальные имена/адреса/заказы
  замазаны.

## Машинные гейты

- `pnpm check:public` — ищет запрещённые файлы и паттерны в tracked
  файлах; входит в `pnpm verify`.
- GitHub secret scanning + push protection — блокирует распознанные
  секреты до попадания в репозиторий.
- Dependabot — обновления зависимостей и security alerts.
- `review-gate` + label `reviewed` — ревью не-автором.

## Если секрет всё же попал

1. Немедленно отозвать/ротировать секрет у провайдера.
2. Удалить из рабочей копии и из истории (`git filter-repo`/BFG) только
   с явного разрешения владельца; force-push — отдельное решение.
3. Проверить GitHub secret scanning, логи доступа, уведомить владельца.
4. Записать инцидент в `docs/quality/audits/` без самого секрета.

## Перед PR

- [ ] `pnpm verify` зелёный, включая `check:public`.
- [ ] Нет реальных ПДн и секретов в диффе, тестах, фикстурах,
      скриншотах.
- [ ] Новые поля с ПДн имеют назначение в `docs/concept/product.md` /
      `docs/legal/context.md`.
- [ ] `.gitignore` не ослаблен.
