# Спринт 1: онбординг продавца + auth

Статус: **BUILDING**, cycle 5. S1-1 auth, S1-2 shop, S1-3 products и
S1-4a admin UI смержены 27.11.2026 (PR #12/#14/#16/#18); следующий —
S1-4b products UI.
Дата планирования: 27.11.2026.
Change: `02-seller-onboarding` (валиден strict).
Бюджет: 4–6 циклов по 60–90 минут; церемонии ≤ 20–25%.

## Sprint Goal

Продавец может войти по российскому номеру, создать магазин и
опубликовать товар, который сразу появляется на витрине Local Hand.

Наблюдаемый результат: на preview продавец проходит путь
`login → shop → product → publish`; товар виден на `/` и в магазине;
второй продавец не может изменить чужой магазин/товар.

## Критерии приёмки спринта

- [ ] Продавец входит по dev-OTP на preview; неверный/просроченный код —
      отказ; телефон/код не в логах.
- [ ] Продавец без магазина создаёт магазин; slug уникален; чужой
      магазин недоступен (404).
- [ ] Продавец создаёт товар, публикует его; товар виден на витрине;
      скрытый товар исчезает.
- [ ] Seller admin работает на 320 и 1440; loading/empty/error; фокус и
      клавиатура.
- [ ] Authz-тесты: без сессии 401, чужой ресурс 404; rate-limit 429.
- [ ] `pnpm verify`, `openspec validate --all --strict`, preview smoke —
      зелёные, evidence записан.
- [ ] Change заархивирован, `specs/` обновлены.

## Вне скоупа

- Buyer-auth, корзина, checkout, ЮKassa, СДЭК.
- Цифровые товары, AI-агент, owner-admin, модерация.
- Загрузка фото в S3; `imageUrl`/плейсхолдер.
- Реальный SMS-провайдер в preview; dev-адаптер, прод-ключ перед
  релизом.
- Полная юридическая проверка оферты/ПДн; тексты — отдельный пакет.

## Риски и решения

- **SMS-провайдер.** В preview dev-код; реальный adapter (SMS.ru) готов,
  ключ — перед прод-релизом. Если ключ не появится, спринт всё равно
  закрывает auth-flow и UI.
- **OTP-абьюз.** Rate-limit, TTL 5 мин, 5 попыток, generic 401.
- **Публичный репозиторий.** Только фейковый demo-телефон; никаких ПДн
  и ключей.
- **Объём.** При перерасходе режем настройки магазина и desktop-
  полировку, не authz и не публикацию товара.
- **Фото.** Без загрузки; карточки на плейсхолдере, S3 — следующий
  change.

## План циклов

1. Auth: схема, контракты, OTP, сессия, тесты.
2. Shop: API, slug, публикация, тесты.
3. Products: API, публикация/скрытие, authz, тесты.
4. Seller admin UI: login/onboarding/shop + применимые loading/empty/
   error, mobile/desktop и a11y из 4.5.
5. Seller admin UI: товары + остаток mobile/desktop и a11y из 4.5.
6. Security/evidence, e2e, docs, архив; review/retro.

## Старт

Сборка начата 27.11.2026 после явной команды владельца. Cycle 1–3
закрыты (S1-1 auth, S1-2 shop, S1-3 products); далее S1-4a admin UI по
плану циклов.
